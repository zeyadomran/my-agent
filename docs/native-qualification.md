## Quit regression evidence

An initial `CloseMainWindow=false` result did not establish a close failure and was excluded. One delivered close exited after the debugger disconnected, establishing that an inspector can hold process exit.

The decisive comparison used a parent retaining the actual spawned Electron `ChildProcess` exit event and a separate inspector helper. Main's reported PID matched the owned child. On the original lifecycle, scheduled `BrowserWindow.close()` followed by helper termination exited with code 0, while scheduled `app.quit()` remained alive beyond the same five-second observation after helper termination. A later second Quit retired that original app with code 0. No broad process kill was used.

The correction cancels the first quit cycle before closing the window, honors its unload decision, retires the service after accepted closure, and starts the final quit in a later event-loop turn. The same driver then observed Quit exit with code 0. An independently delivered ordinary native window close also exited with code 0. Native dialog button actions were exercised against the exact owned dialog; active provider identity checks included process creation identity to avoid treating a reused PID as the old instance.
