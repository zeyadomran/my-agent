# Claude Code adapter

[claude-code.ts](claude-code.ts) exports `createClaudeCodeAdapter(options?)`, implementing the main-only [ProviderAdapter](../../shared/contracts.ts). Main resolves the profile working directory against its stable workspace base before calling it. Optional `requestTimeoutMs` and `promptTimeoutMs` default to 30 seconds for connection probes and 120 seconds for turns. Each probe or turn owns a finite Claude CLI process through the [shared transport](README.md); this adapter does not introduce another launcher.

## CLI policy and authentication

The installed CLI qualified for this implementation is Claude Code 2.1.303. The adapter uses print mode with verbose stream-JSON input/output and partial messages. A probe sends a harmless short chat with native session persistence disabled. It uses the configured executable and environment, preserves existing CLI authentication, and does not require an API key or change global configuration.

Every launch supplies `--safe-mode`, `--tools ''`, `--disallowedTools '*'`, strict empty MCP configuration, disabled slash commands, `dontAsk`, `--permission-prompts none`, and `--no-chrome`. The initialization frame must report empty tool and MCP lists. Unexpected tools, tool blocks, or permission requests fail and retire the process; the app supplies no approval or tool handler. Managed policy still applies. These controls rely on the configured Claude executable and do not establish a security sandbox or bypass enterprise policy.

`--safe-mode` preserves normal authentication while disabling customizations. Installed help explicitly states that `--bare` skips OAuth/keychain authentication, so this adapter does not use it. The [current CLI reference](https://code.claude.com/docs/en/cli-reference) describes stream flags, tool controls, safe mode, and sessions; installed help was checked separately where its description differs. Older CLIs that reject required controls fail rather than silently weakening policy.

Profile arguments support `--model`, `--effort`, `--max-turns`, `--max-budget-usd`, and `--autocompact`, using separate or equals-form values. An explicit profile model takes precedence over an argument model. A Node CLI entrypoint may precede those options as a literal script argument. Other arguments, positional prompts, session selectors, fallback models, settings/plugin overrides, debugging, and protocol/permission overrides are rejected. `testConnection` reports `invalid-input` for incompatible arguments; run failures use the existing provider failure contract. Arguments and environment values never enter diagnostics or renderer state.

## Sessions, context, and terminal events

The adapter creates its own random UUID and resumes only metadata with its version/origin, matching profile identity and configuration fingerprint, a valid owned UUID, a reusable flag, and an available completed assistant marker. Native metadata contains no transcript or plaintext credentials. A foreign, changed, incomplete, or unrecognized checkpoint starts a fresh session carrying available app context within the disclosed encoded handoff budget.

Before a prompt can mutate native history, the adapter yields a non-reusable session checkpoint and waits for the consumer to persist it before advancing the iterator. After a validated successful result and natural exit status 0, it yields a reusable checkpoint at the incorporated assistant message, again waiting for persistence. Consumers must persist each session event before requesting the next one and abort/return the iterator if persistence fails. App transcript persistence and service assembly remain the main application's responsibility.

Resume preserves Claude's persisted native context and supplies complete app messages after its saved marker, including messages added by other providers. An exact missing-session result before initialization or text, followed by exit status 1, permits one fresh-session recovery with available app context within that budget. Authentication, arbitrary errors, malformed output, and errors after initialization/text never trigger that recovery.

The shared handoff measures the exact serialized Claude user envelope, including nested JSON escaping, within its 256 KiB encoded-line budget. It preserves all history that fits or the maximal recent suffix of whole messages; a provider notice and durable assistant-message `contextHandoff` counts disclose any omitted earlier messages. The separate `context` checkpoint must be persisted before submission, without advancing the native session checkpoint early. Full saved history is retained. Oversized current input returns actionable `input-too-large` guidance without slicing it or making a summarization call. Claude may reject input at a smaller context limit or apply its own native context handling/compaction. Native persistence does not promise unlimited model context.

Only current-session text deltas and any remaining final assistant text are emitted. Final snapshots and result text are checked without repeating already streamed output. Session/message identity, tool absence, result success, and exit status must agree. Missing results, contradictory output, malformed frames, and nonzero exits yield one sanitized failure. Stop, iterator return, disposal, deadlines, and failures await shared process retirement. If retirement cannot be confirmed, a consumed run reports sanitized `failed` even when its signal was aborted; `stopped` requires successful retirement. Interrupted checkpoints remain non-reusable so the next run cannot silently inherit an uncertain partial turn.

## Validation boundary

[claude-code.test.ts](claude-code.test.ts) is the canonical public adapter flow. It uses the real shared transport, an [owned external CLI fixture](fixtures/claude-agent.mjs), real temporary storage with a controlled encryption boundary, and synthetic text. It covers probe, streaming without duplication, checkpoint persistence, storage/adapter reopen, native resume, cross-provider replay, stale recovery, unsafe metadata, material startup/authentication/protocol failures, context refusal, cancellation, iterator return, and disposal. Process instances are checked for retirement before temporary cleanup. There is no duplicate parser-only happy flow or GUI suite.

Bounded native qualification on 2026-10-19 used the actual adapter and existing Claude authentication in an owned temporary working directory: probe passed, chat streamed and completed, and a recreated adapter resumed the same UUID while recalling its harmless token plus a newly supplied cross-provider token. No auth files or provider logs were inspected or copied. An initial 30-second bounded resume attempt returned `provider-failed`; a later unmodified probe/chat/resume run passed with a 45-second bound. The cause of that initial native failure was not established. This is provider interoperability evidence from the source adapter, not assembled Electron UI qualification or an enterprise-policy guarantee.
